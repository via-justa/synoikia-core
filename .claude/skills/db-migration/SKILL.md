# Database migration

Migrations are generated by Drizzle Kit from `packages/core/src/db/schema.ts` into `packages/core/drizzle/` and applied by `openDatabase()` on startup. Every existing install runs them on upgrade, so a migration must keep what users already have working.

## Steps

1. **Edit the schema** in `packages/core/src/db/schema.ts`, and update the code that reads or writes the changed columns.

2. **Generate** the migration, named after the change in snake_case (it becomes the tag, e.g. `0010_instance_notes`):

   ```sh
   pnpm --filter @synoikia/core db:generate --name <short_name>
   ```

   This writes `drizzle/NNNN_<short_name>.sql`, a snapshot in `drizzle/meta/` and a journal entry. Never edit `drizzle/meta/` by hand, and never edit a migration that is already on `main`, since installs may have run it. If the generated file is wrong, delete all three outputs, fix the schema and generate again.

3. **Review the SQL.** SQLite can't alter most column properties, so Drizzle may rebuild a table (create a new one, copy the rows, drop the old one, rename). Check that the copy keeps every column you meant to keep.

4. **Add a data migration** if existing rows need new values, such as a backfill, a moved value, or keeping old behavior for rows created before the change. Append the statements to the new `.sql` file, each after `--> statement-breakpoint`, with a `--` comment saying why. `0002_access_levels.sql` and `0007_registry_scopes.sql` are examples. The default is that upgrades keep working the way they did: nothing gains access and nothing that ran with approval starts running without it.

5. **Test it** in `packages/core/test/migrations.test.ts`. Add a `describe` that builds a database at the previous tag with `databaseAt('<previous tag>')`, inserts rows the way the old schema stored them, then opens it with `openDatabase({ dataDir: dir })` to run the new migration and checks the result. Follow the existing `registry scopes migration` block.

6. **Run the checks:**

   ```sh
   pnpm --filter @synoikia/core exec vitest run test/migrations.test.ts test/db.test.ts
   pnpm --filter @synoikia/core typecheck
   pnpm test
   ```

7. If the change affects the data model in `docs/design/07-data.md` (§7), update it in the same PR, in the style that `docs/design/README.md` sets.
