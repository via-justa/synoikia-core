# §12 Security

## Trust boundaries

| Boundary                    | Controls                                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Internet → admin            | Separate port that the proxy does not publish (§11). Sign-in with TOTP or OIDC, sessions, CSRF, lockout (§6.1).                                                                                                                                                                                                                                                                       |
| Internet → MCP endpoint     | Authentication mode for each endpoint, scoped tokens and grants, 403 outside the scope, access ceiling `read` by default (§6.2, §6.3).                                                                                                                                                                                                                                                |
| MCP client → upstream       | The sandbox gives access only to the binding. The gate decides each call (§5.2). Then the plugin `invoke` runs.                                                                                                                                                                                                                                                                       |
| Model → configuration       | No MCP tool changes configuration. The sandbox has no database access.                                                                                                                                                                                                                                                                                                                |
| Plugin → core secrets       | Child process, Node permission model, clean environment, secrets of its own instance only (§4.4).                                                                                                                                                                                                                                                                                     |
| Plugin supply chain         | Pinned versions, sha256, optional pinned-key signatures, warnings for unsigned plugins, prebuilt packages only (§4.2, §4.3).                                                                                                                                                                                                                                                          |
| Approvals                   | Only a signed-in human with a TOTP proof in that browser (a new code for locked operations) decides, on the approval page. The answer of the calling client never approves, except opted-in form approvals of plain writes. The approval card only shows state. Hash-bound, single use, typed confirmation, parameters in memory only, access and targets checked again (§5.3, §5.7). |
| Plugin change during a call | The gate refuses a call if the bundle changed after the call was gated (§5.2).                                                                                                                                                                                                                                                                                                        |
| Secrets at rest             | AES-256-GCM, master key outside the database, APIs that only write secrets, redaction everywhere (§5.5, §7.2).                                                                                                                                                                                                                                                                        |
| Audit                       | Append-only. It records calls, searches, configuration, sign-ins and plugin events. The model never sees it.                                                                                                                                                                                                                                                                          |

## Remaining risks

1. An installed plugin that is malicious can give wrong classifications or locks for its own upstream. It can also connect to any network host. The trust flow (§4.3) and an egress policy (§11) reduce this risk. Core does not.
2. `external` mode without JWT verification depends only on the network placement.
3. SQLite allows one writer, so there is one core process.
4. Core decides if a call is a read or a write once, before the approval wait. A sync from the same bundle can change an operation that has its own `ask` from read to write while its approval is open. The approved call then runs without `prepareWrite` and without the write budget. A human approved these exact parameters, and the risk lasts for one approval only.
5. A session grant (§5.8) lets a client run each `ask` operation of one endpoint without a human, for up to `sessionGrantMaxHours`. During that time, a client under prompt injection can make these calls. Locked and typed-confirmation operations, the write rate limit, revoke and the audit log limit this risk.
6. Without the approval card, the agent shows the approval link as text. An agent under prompt injection can show another link. The real page needs a sign-in on the MCP listener, and a decision needs a TOTP proof, as for URL elicitation.
7. A parked execution keeps an isolate and the real parameters in memory until its approval ends. The parked limits (§5.6) bound this.
